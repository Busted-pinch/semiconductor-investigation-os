Phase I - Core Investigation Platform
The committed FYP deliverable
A working, evaluatable multi-agent RCA system. Everything else builds on this.
F1
CNN defect classifier
ResNet-18 trained on WM-811K, 8 defect classes, ≥92% accuracy. Data augmentation for class imbalance. Train/val/test split with confusion matrix.
F2
GradCAM++ heatmaps
Visual attribution on every CNN prediction. Overlay on wafer image showing which spatial region drove the classification. Saves as image output.
F3
IoT process simulator
6 parameters: chamber temp, RF power, gas flow, etch duration, pressure, rotation. Baseline values and noise calibrated against real SECOM sensor distributions. Anomaly injection (step/drift/spike) is causally linked to F4's mapping, not independently randomised — each injected fault traces to a literature-cited defect-process rule.
F4
Defect–process causal graph
Literature-derived, citation-backed graph (built first, before any code): each defect class → responsible process parameters → expected deviation direction → source paper. Not a static guess file — every edge traces to Pillar 1 research. The ground truth all agents reason against, and the source of F3's anomaly injection rules.
F5
Vision Agent
Wraps F1+F2. Accepts wafer image, returns defect class, confidence score, and GradCAM++ heatmap. Publishes findings to message bus.
F6
Process Correlation Agent
Subscribes to IoT stream (F3). On defect alert, retrieves parameter window for that wafer run. Flags which of the 6 parameters deviated and by how much.
F7
Counterfactual Agent
Takes CNN embeddings + deviated process params. Runs DiCE to find minimal parameter changes that would have prevented the defect. Each candidate counterfactual is checked against physically feasible bounds (Algorithmic Recourse framework) before being output — no "reduce gas flow below its physical minimum" nonsense. Outputs validated "reduce X by Y" statements.
F8
Coordinator Agent
Receives all three agents' outputs. Applies defect–process causal graph (F4) to validate hypotheses. Commits to a top root cause but ranks alternatives with confidence scores rather than asserting a single unranked verdict — an honest determination, not a false-certainty one.
F9
RCA report output
Structured JSON + human-readable text report. Fields: defect class, confidence, deviating params, ranked root cause hypotheses (top + alternatives with probabilities), counterfactual recommendation.
F10
Evaluation framework
Ablation study: CNN-only vs CNN+GradCAM vs full multi-agent. Measure time-to-RCA vs human baseline (4–24 hrs). Fault-recovery rate: inject known faults into the calibrated simulator (F3) and measure whether the system correctly identifies them — the core validity metric given no real fab ground-truth exists.
F11
Decision Impact Estimator
Converts the Coordinator's ranked verdict into an urgency tier and estimated cost-of-delay, using published fab downtime/yield-loss figures (not invented numbers). Thin formula/lookup layer — the actual "decision support" output engineers act on.
Phase II - Knowledge-Driven Investigation
From research demo to trusted system
Uses every Tier 1 component. Adds memory, confidence, and multiple entry points.
Requires: F1–F10 fully complete and stable before starting any Tier 2 feature
E1
Knowledge Graph
Structured graph: defect nodes → process step nodes → parameter nodes → failure mode nodes. Extends F4 from static file to queryable graph. Agents query it for causal paths.
E2
Historical case base
Database of past investigations with confirmed root causes and outcomes. When a new defect arrives, similarity search retrieves the top-3 matching cases with their resolutions.
E3
Equipment state model
Tracks per-chamber: runs since last PM, pump health score, days since last clean, electrode age. Process Agent uses this to weight hypotheses — worn pump + pressure variance = high confidence pump wear.
E4
Bayesian confidence fusion
Coordinator fuses confidence from: CNN score, sensor deviation magnitude, KG causal strength, case base match similarity. Outputs a single calibrated probability per root cause hypothesis.
E5
Agent debate protocol
When Vision Agent and Process Agent contradict (e.g. pattern looks thermal but sensors show pressure), Coordinator runs structured evidence weighting before committing to a root cause verdict.
E6
Multiple entry points
Investigation can start from: wafer image, sensor alarm threshold breach, yield drop on a lot, or manual engineer query. Each entry point routes to the appropriate agent first, not always Vision.
E7
Alternative hypotheses
Coordinator outputs ranked list of root causes with probabilities, not just the top one. Engineer sees: RC-01 pump wear 76%, RC-02 controller drift 14%, unknown 10%.
E8
Engineer dashboard
Web UI showing: active alerts, open investigations, chamber status tiles, RCA report viewer. No coding required to use the system — designed for a process engineer with no ML background.
Phase III - Adaptive Manufacturing Intelligence
The real fab vision — learns from every investigation
Uses all of Tier 1 and Tier 2. Each investigation makes the system smarter.
Requires: E1–E8 complete. Specifically E1 (KG), E2 (case base), and E3 (equipment state) are prerequisites for every Tier 3 feature.
A1
Engineer feedback loop
After an investigation, engineer confirms or corrects the root cause. Confirmed: case stored in E2, KG edge confidence updated in E1. Corrected: KG penalises wrong path, learns the right one.
A2
KG confidence evolution
Every confirmed or corrected investigation updates Bayesian weights on KG edges. Over time, the graph's confidence values reflect real fab experience, not just literature priors.
A3
Forward simulation
"If I skip this PM for 20 more runs, what is the defect probability?" Uses equipment state model (E3) + historical degradation curves + KG to project defect risk forward in time.
A4
Predictive maintenance alerts
Proactive alerts before defects occur. Chamber 3A pump health trending toward failure — alert fires at run 260, before the 250-run threshold that historically causes edge rings.
A5
SCADA / PLC connector
Swap the IoT simulator (F3) for a real connector to fab equipment. Zero agent code changes — only the data source changes. Validates the Tier 1 architecture decision.
A6
Cross-chamber pattern learning
If Chamber 2A and 3A both show edge rings after similar run counts, the system infers a systemic issue (batch of consumables, process recipe change) rather than isolated equipment failure.
A7
Yield trend analytics
Dashboard analytics: defect rate per chamber over time, root cause frequency distribution, MTTRC trend, PM effectiveness scoring. Gives fab managers a quality intelligence view.
